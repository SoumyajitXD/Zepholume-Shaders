The main settings screen exposes `<profile>` plus Lighting, Sky and Atmosphere, Clouds, Water, Weather and Performance submenus. Existing English profile labels, option values, screen labels and option tooltips are preserved in `shaders/lang/en_US.lang`.

Quality overrides are capped by the selected baseline. Exposure, contrast and saturation remain common option 1 across all presets; finalization changes no profile values. Low's raw waves switch remains 1, but its water tier is below the function's tier-2 displacement gate, so no Low wave displacement is enabled.

Fresh focused command: `scripts/tests/profile-config-tests.ps1` **PASS** for all five profiles, defaults, ranges, screen controls, labels, tooltips, quality distinctions and malformed-input rejection. This is a configuration check; actual menu behavior has not been observed for the final artifact.

The current [Iris shader settings reference](https://shaders.properties/current/reference/shadersproperties/shader_settings/) documents numeric define options with permitted-value comments, `screen`/sub-screen declarations, `<profile>`, `profile.<name>` assignments, and language label/tooltip keys. The pack retains those forms; no unsupported profile property or Iris-exclusive required feature is introduced.

## Dimension topology and routing

The source has 14 root vertex/fragment program pairs: 28 stages at root and complete corresponding 28-stage sets in `world0`, `world-1` and `world1`, totaling 112 program files. Overworld uses the shared base path. Nether and End wrappers define `ZEPH_DIM_NETHER` and `ZEPH_DIM_END`; their existing analytical Overworld sky/celestial-water exclusions remain.

This complete topology matters because the documented legacy `worldN` scheme loads dimension-folder programs instead of root programs when those folders exist. Iris maps the three folders to the vanilla dimensions, with `world0` also used for modded dimensions under the legacy scheme. Modded-dimension rendering is unqualified. See the current [Iris dimension reference](https://shaders.properties/current/reference/miscellaneous/dimension_properties/).

Terrain water is classified only by pack-local material `10001` mapped to `minecraft:water`; other translucent terrain retains the ordinary scene route. All four `gbuffers_hand.fsh` routes declare `ZEPH_LIGHTMAP_LIT_PROGRAM` before including the shared fragment implementation. There is no explicit `gbuffers_hand_water` source; the current [Iris gbuffers reference](https://shaders.properties/current/reference/programs/gbuffers/) specifies fallback to `gbuffers_hand`. This documents the intended translucent-hand route, not a tested loader execution. The same reference identifies `gbuffers_water` as translucent terrain, so it cannot be treated as water-only geometry.

## GLSL and loader boundary

Every program retains `#version 330 compatibility`; no extension, extra colour target, compute/geometry/tessellation stage, shadow pipeline or loader-required feature flag is added. The source uses legacy attributes/matrices and existing uniforms. Shader libraries do not branch on `MC_VERSION`, `IS_IRIS` or `OCULUS`; existing optional `MC_RENDER_STAGE` handling in the sky path has a fallback. Absence of a version branch is not proof that every game/loader version supplies identical inputs.

The current [Iris compatibility-profile guidance](https://shaders.properties/current/how-to/compatibility_vs_core/) recommends compatibility-profile source and explains that modern Minecraft loaders transform legacy inputs internally. Therefore standalone compilation of this source is distinct from compilation of real loader-transformed output. The retained lightmap-coordinate conversion uses `gl_TextureMatrix[1] * gl_MultiTexCoord1`, matching the documented block-light X and sky-light Y interface in the [Iris attribute reference](https://shaders.properties/current/reference/attributes/gl_multitexcoord1/).

## Unresolved visual boundary

The confirmed source limitation is analytical water reflection/highlight response without local skylight occlusion. Lightmap coordinates are available, but ambient skylight is not directional visibility. No unvalidated attenuation or global night-brightness tuning is introduced. The severity and appearance in covered/nighttime Minecraft water remain unverified. Waterfall correction, hand lighting, cave/interior balance, alpha/depth/sorting and in-game performance likewise need gameplay evidence before receiving visual or performance claims.
