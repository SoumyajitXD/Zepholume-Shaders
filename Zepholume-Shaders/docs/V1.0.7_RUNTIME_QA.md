## Interfaces and profiles

The five selectable profiles remain Potato, Low, Balanced (source default), High and Ultra. Each declares 15 assignments. No sixth selectable Ultra Lite profile was added. Existing numeric options, allowed-value comments, screens, profile syntax and language keys follow the [official Iris settings reference](https://shaders.properties/current/reference/shadersproperties/shader_settings/). The existing `en_US.lang` filename is intentional: Iris's [LanguageMap implementation](https://github.com/IrisShaders/Iris/blob/26.1/common/src/main/java/net/irisshaders/iris/shaderpack/LanguageMap.java) lowercases the filename before indexing its locale. An unnecessary case-only rename was rejected.

There remain 14 program pairs at root and complete sets in `world0`, `world-1`, `world1`: 112 program files. The [legacy dimension contract](https://shaders.properties/current/reference/miscellaneous/dimension_properties/) requires complete folders and routes modded dimensions through `world0`; this does not establish correct custom-dimension visuals. The [lightmap interface](https://shaders.properties/current/reference/attributes/gl_multitexcoord1/) identifies block light X and sky light Y and recommends texture matrix conversion, retained here. This ambient sky coordinate is not directional roof visibility.

## Safe operator procedure

1. Use a separately named disposable launcher instance with its own game directory. Resolve matching Minecraft, Java, loader, Iris/Oculus and rendering dependencies from official metadata first. Do not repoint a personal installation or copy personal saves/accounts. Create a new disposable world with recorded seed.
2. Hash the exact candidate and preserved V1.0.6 archive. Install each intact ZIP only in that disposable instance. Select Balanced explicitly; clear only that disposable instance's prior shader-option overrides. Verify five menu profiles, labels and options, recording screenshots.
3. Enable the loader's documented shader-debug output, reload the candidate, retain complete `latest.log` and patched shaders locally, and confirm the candidate filename is selected. Run standalone checks on the retained loader output separately; the existing generated variants do not simulate the loader patcher.
4. Freeze resolution, FOV, position, yaw/pitch, render/simulation distance, time, weather, resource pack and options. Capture matched baseline/candidate scenes in each tested profile: clear daytime horizon and vertical view at fogStart/midpoint/fogEnd; rain/fog transitions; large cloud faces with changed mesh triangulation/viewpoint; sunrise/sunset; water top and waterfall facets with sun/moon in front, tangent and behind; dry translucent blocks; empty/opaque/translucent/emissive hand; zero-skylight cave water with and without torch; underwater/lava/powder-snow; Nether/End transitions.
5. Accept fog only when distant geometry/clouds fully blend at the configured endpoint without triangle seams and midrange depth remains readable. Accept highlights only when local light/view sidedness is plausible and transitions remain smooth. Inspect alpha/sorting separately. Covered reflections remain a known limitation, not a fixed acceptance claim.
6. Benchmark paired fixed scenes following `BENCHMARK_PROTOCOL.md`, using the exact V1.0.6 ZIP as a newly recorded Phase 1 control rather than silently rewriting the historical V1.0.3 control. Preserve raw CSV and manifests; report run counts, median and p95 frame time, FPS and A/A noise. Investigate candidate regressions above +3% median or +5% p95; those thresholds alone do not establish significance.
