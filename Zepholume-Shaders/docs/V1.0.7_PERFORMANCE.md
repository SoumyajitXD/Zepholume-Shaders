# V1.0.7 Phase 1 performance and portability review

Reviewed 2026-10-29, after water/atmosphere integration. This is a separate, read-only production review. No additional GLSL optimization was integrated by this workstream. Controlled Minecraft frame-time, FPS, median and p95 performance are **NOT MEASURED**. Neither a smaller source expression nor a successful compiler result establishes a game speedup.

## Source-bound specialization

New `scripts/tests/v107-specialization.py` validates the source inventory and every variant hash through the existing variant-loader contract before inspecting preprocessed function bodies. It excludes uncalled helper definitions when checking main call sites, deduplicates identical mock-vendor source contexts, and makes no driver dead-code-elimination assumption.

The baseline and integrated sets both contain **5,040 logical mappings / 272 unique stage sources**. Each has 168 source contexts per profile (three dimensions, two macro models, fourteen programs and two stages). The targeted specialization check passes **96 cases per set**, covering:

| Profile/path | Verified preprocessed-source behavior |
| --- | --- |
| Potato water fragment | `zephWaterSurfaceLinear` disabled body returns immediately; main never calls it |
| Potato scene fragment | No scene-lighting/material call or local normal normalization in terrain main |
| Potato cloud fragment | Main excludes sun direction, day/night tint and rim-light calculation |
| Potato / Low water vertex | `zephMoveWater` has no sine/cosine; no displacement work enabled |
| Balanced / High / Ultra water vertex | Wave trigonometry remains enabled, preserving meaningful profile distinction |
| Low clouds | Basic lighting present; twilight/rim absent |
| Balanced clouds | Twilight present; high-tier rim absent |
| High / Ultra clouds | Rim path present |
| Nether / End water | Celestial half-vector and local-incidence calculations absent for all enabled profiles |

Baseline source-manifest SHA-256: `60A46C3C5FBF2114E3B72476563D7E1BDA4BAF776B9A7885378`.

Integrated source-manifest SHA-256: `41896FCA2D23FD8990F6FF6774FCCBD191790E317ECF34CC02D2059BCBCF57E5`.

The Potato cloud **vertex** main still calculates the normal/elevation varying in all six dimension/macro contexts. This is pre-existing behavior in both snapshots. The Potato fragment does not consume it, so linker optimization may eliminate it, but the preprocessed vertex source does not explicitly omit it. This is a deferred source-simplification candidate, not a confirmed hardware cost or a new regression.

## Integrated change costs and review

| Correction | Original operations | New operations / tradeoff |
| --- | --- | --- |
| Air full-fog endpoint | Hermite factor multiplied by horizon/weather density and clamped | Existing factor multiplied by `density + (1-density)*factor`; approximately one scalar subtraction, multiply and addition added; no sample, pass or transcendental |
| Cloud full-fog endpoint | Clamped linear factor times weather density, then clamp | Endpoint-preserving polynomial; same small additional scalar expression, final range bounded for loader weather `[0,1]` |
| Cloud mesh distance | Per-vertex length, one scalar distance varying | Affine vec3 position varying and per-fragment length: two additional scalar varying components and fragment dot/square-root-class work; vertex length removed. Potential fragment cost increase also applies to Potato |
| Water local illumination | World-horizon weights plus half-vector/lobe | Positive normal/light dot, local incidence scaling and view-side guard for each active lobe. Can omit half-vector work on unlit/back-view facets; per-fragment branch divergence and net cost unmeasured |

No new texture lookup, render target, mandatory pass, temporal state or buffer dependency is introduced. Water uses the existing `NdotV`; no extra normalization is added for the local view test. The water correction intentionally changes slanted highlights; it is not image-equivalent to the defect. Fog strength changes inside the range are also intentional. The cloud position change is reference-equivalent to the correct fragment distance, not to the old interpolated corner distances. Do not characterize these correctness changes as neutral optimizations.

## Ranked optimization candidates

| Priority | Candidate | Expected value / evidence | Decision and acceptance criteria |
| --- | --- | --- | --- |
| 1 | Explicitly gate cloud normal/elevation varying behind `ZEPH_EFFECTIVE_CLOUD_QUALITY > 0 && ZEPH_EFFECTIVE_CLOUD_TIER >= 1` in both stages | Removes visibly unnecessary lower-tier source work; current linker may already remove it | Deferred with lead agreement while integrated variants are frozen. Require profile/wrapper links, source-body omission checks and native before/after pixel equivalence; measure target driver before claiming speedup |
| 2 | Reuse one world-space celestial elevation at each water/lighting/sky call site | Source currently repeats bounded direction/world-up computations through shared helpers | Deferred: compilers may already perform common-subexpression elimination. Require native compiled evidence or controlled timing benefit and float32 horizon-boundary equivalence; preserve camera-basis contract |
| 3 | Move only draw-uniform celestial quantities to an existing cheaper stage/interface | Potentially avoids repeated per-fragment uniform-derived math | Deferred: introduces varying/uniform ownership and stage-interface complexity, with no demonstrated gain. Must preserve numerical day/night transitions and cross-loader inputs; no new pass |
| 4 | Remove unused material arguments / unused declared uniforms | Readability benefit; little expected GPU value after dead-code elimination | Deferred: avoid interface churn for no measured rendering benefit |
| Rejected | Replace cloud fragment distance with interpolated scalar corner length to save fragment work | Removes the correctness fix | Rejected: restores demonstrated triangulation-dependent fog |
| Rejected | Remove required lightmap fetch or broadly disable material response to reduce samples/arithmetic | Can reduce source work | Rejected: reintroduces lighting defects or changes intended profile appearance without a justified alternative |

No speculative optimization was retained merely for a source instruction-count reduction. The immediate engineering value is confirmed correctness plus auditable compile-time specialization coverage.

## Numerical and portability review

The modified fog polynomial preserves zero/one endpoints and is monotone over the existing atmosphere-density interval `[0.6888,1.12]` and cloud interval `[0.76,1]`. Existing non-positive-range guards remain ahead of division. The fragment position interpolation removes a nonlinear varying; fragment length remains nonnegative. Water normal/light directions use existing bounded normalization; local incidence is nonnegative, view cosine is clamped, and output still clamps negative surface colour. These statements assume finite loader inputs and the documented weather range; arbitrary NaN/Inf external uniforms are not qualified.

No version-specific extension or vendor branch is added. New arithmetic and the vec3 varying stay within the existing GLSL 330 compatibility architecture. Standalone variant generation uses six mock vendor labels and two macro models; those labels do not execute six vendor drivers or two shader loaders. The targeted native water library regression ran on **Intel UHD Graphics 730, driver 32.0.101.7085, OpenGL/GLSL 4.6**. AMD, NVIDIA and Intel discrete native execution are **NOT TESTED**. Integrated native and glslang stage/link counts belong to the lead Phase 1 report.

Provisional real-game regression investigation thresholds (+3% median frame time, +5% p95) remain **UNASSESSED**. Follow-up controlled paired runs must fix candidate ZIP hash, hardware/driver, scene/camera, loader/mod set, resolution, render distance, profile, warmup and capture duration; retain run counts and A/A noise controls. Clouds covering the screen, water covering the screen, rain, dawn/dusk, vertical water and mixed transparent geometry are relevant difficult cases; open terrain and Potato are relevant lower-cost controls.

## Reproduction

From the nested pack directory:

```powershell
python scripts/tests/v107-specialization.py --variant-root artifacts/v107-phase1/variants --source-root shaders --baseline-root artifacts/v107-phase1/baseline-variants --baseline-source-root artifacts/v107-phase1/baseline-shaders --output <fresh-report.json>
```

The current retained result is `artifacts/v107-phase1/specialization.json`. Changed/missing shader inputs or corrupted variant files cause the existing manifest/hash contract to fail before specialization is checked. This command does not launch Minecraft, measure GPU instruction counts or collect frame times.
