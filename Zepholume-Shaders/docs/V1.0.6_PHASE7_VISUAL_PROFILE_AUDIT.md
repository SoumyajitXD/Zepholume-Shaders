## Confirmed defect and correction

The Phase 6 audit missed a coordinate-space contract. Iris documents `sunPosition` and `moonPosition` in view space, and `gbufferModelView` as the player-to-view transform. A normalized view-space vector's `.y` is camera-relative elevation. It is not world elevation. At fixed world time, pitching the camera rotates this component and changes daylight, twilight, fog, and celestial visibility weights. A world-up surface can likewise change material, dimension, hemisphere, and cloud shading when its view normal's `.y` is used as upwardness.

The correction declares the existing standard `gbufferModelView` uniform in `common.glsl`. `zephWorldUpView()` normalizes its second column, the transformed player-space up direction; translation is excluded. `zephWorldElevation(viewDirection)` compares a normalized view vector against that up direction. No matrix inverse, texture read, render pass, or new feature is introduced. Camera rotations preserve the dot product: `(R direction) dot (R up) = direction dot up`. Existing celestial normal/light and sky/light dot products stay in view space, where they already agree.

| Production library | Corrected world-relative calculation |
| --- | --- |
| `common.glsl` | Shared daylight and twilight helpers use world elevation |
| `lighting.glsl` | Day/night mixing, Nether/End upward fill, High/Ultra hemisphere fill |
| `materials.glsl` | Upward surface shaping |
| `fog.glsl` | Atmospheric day and twilight color weights |
| `water.glsl` | Day/night and sun/moon horizon visibility weights |
| `fragment.glsl` | Air-fog horizon receives normalized world elevation |
| `cloud_vertex.glsl` | Cloud facet upwardness |
| `cloud_fragment.glsl` | Day/night, twilight, sun lift and top-facet rim |
| `sky_vertex.glsl` | Sky gradient upwardness, with the shared common include |
| `sky_fragment.glsl` | Analytic sky dawn, daylight and star visibility |

Only world-relative elevation was changed. Lightmap sampling, source alpha, color grade values, exposure/contrast/saturation, water displacement, wave amplitude, quality tiers, dimension routing, and fog range/media formulas retain their prior design. Normalizing the interpolated fog direction also prevents interpolation shrinkage from changing the horizon weight. This can change non-horizontal fog readbacks even with an identity camera transform; it is intentional direction handling, not brightness tuning.

The standard matrix must be populated by synthetic harnesses too. OpenGL uniforms default to zero; a fixture that omits `gbufferModelView` does not reproduce the loader contract. Fresh native evidence must upload identity or the fixture camera rotation before interpreting colors. The root integration report records those GPU results separately.

## Numerical regression and limits

Run `python scripts/tests/camera-space-tests.py --output artifacts/phase7-camera/cpu-reference.json` from the source root. Fresh result: **1,008 cases**, maximum world-elevation error `1.942890293094024e-16`, **800** counterexamples for the original view-Y calculation. The cases include 6 yaw angles, 7 pitches, 3 rolls, and 8 vectors spanning zenith, nadir, horizontal directions, near-horizon celestial directions, and zero. Daylight, twilight, horizon visibility, atmosphere attenuation, and up/fill weights are checked against camera-independent world values. Source contracts cover all ten corrected libraries and reject the old helper mutation. `--inject-view-y` exits 1 on a rotated zenith vector (`0.016857730108665814` versus expected `1.0`), demonstrating that the original defect fails the regression.

This independently proves the coordinate relationship and links the intended consumer expressions to source. It does not execute Iris's transformer, Minecraft uniforms, actual geometry, or screenshot comparisons. Native transformed fixtures and eventual fixed-time camera-pitch screenshots remain separate evidence gates.

They remain unchanged. The underwater fog ramp is continuous and saturates early for tiers above Potato; its endpoint slope change is not a value discontinuity and remains unchanged. No global darkening, new contrast, moon brightness, cave ambient, fog tint or saturation values were selected without gameplay evidence.

## Five-profile audit

The official shader settings syntax permits `<profile>` in the root screen and `profile.NAME = OPTION:value` definitions. The root screen contains one profile control and six defined sub-screens. All five profiles directly assign all 15 numeric options. There is no inheritance or partial override ambiguity. `settings.glsl` exactly matches Balanced defaults. The capability tier is intentionally profile-only; the other 14 controls appear once in the six sub-screens. English profile labels, all option labels, value labels and `option.NAME.comment` tooltips exist. Iris's `LanguageMap` lowercases file names before lookup, so the existing legacy `en_US.lang` spelling is accepted; it is not evidence of the Potato menu failure.

| Profile | Intended distinct source paths | Actual menu/application |
| --- | --- | --- |
| Potato | Quality tier 0; no directional/material/cloud/analytic-water work, no water waves; vanilla-compatible source sky and loader water fog | NOT TESTED |
| Low | Face tier 1; material off; cloud/water tier 1; reduced specular/reflectance, no tier-2 water displacement | NOT TESTED |
| Balanced | Default; face tier 2, material on; cloud twilight and tier-2 water with two waves | NOT TESTED |
| High | Face tier 3 with wrap and hemisphere fill; cloud rim; water fifth-power Fresnel and third wave | NOT TESTED |
| Ultra | Same face tier as High; water reflectance/specular boost and stronger underwater fog/tint values | NOT TESTED |

Presets are genuinely distinct overall, but individual controls have aliases: cloud tiers 3 and 4 execute the same cloud arithmetic; weather tiers 1, 2 and 3 execute the same weather arithmetic. The English weather value labels imply additional quality even though only Off versus On changes production work. These are documented limits, not reasons to invent heavier shader paths. Water tier 4 does differ from tier 3, so Ultra is not identical to High. Low's wave option is 1 but its tier prevents displacement; tier capping is intentional. Whether caps and aliases are intuitive requires an in-game menu review. No profile disappearance or persistence fix is claimed from parser checks.

## Reproducible scene specification

The following is an **unbuilt operator specification**, not a world or screenshot artifact. Use a new disposable creative test world with cheats, seed `106007`, default world generation, no resource packs, and fixed difficulty/biome where relevant. Never alter a protected existing save. Record the exact world generator/version and dimension. Do not reuse generation between different Minecraft versions as if geometry were guaranteed identical. Build the fixture once per version, then preserve that disposable world's state for control/treatment pairs.

Before capturing, freeze time and weather changes (`/gamerule doDaylightCycle false`, `/gamerule doWeatherCycle false`), disable automatic exposure mods, clear effects, and record resolution, GUI scale, FOV, brightness, render distance, simulation distance, cloud mode and graphics mode. Choose and write down each scene's exact `/tp` position, yaw and pitch in its evidence record before the first control capture; reuse those values for treatment. Build a stone/light-gray concrete test wall and floor, dark/white blocks, one torch wall, sealed unlit room, sealed torch-lit room, water pool, leaves, glass, ice and stained glass. Include nearby and distant geometry. A camera marker alone does not freeze animated water/cloud phase; record timestamps and use repeated observations.
