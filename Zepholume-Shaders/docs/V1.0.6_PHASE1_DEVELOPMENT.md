## Confirmed defects and corrections

1. **Windows profile assignment failure.** `scripts/profile-config.ps1` and `scripts/validate.ps1` used a multiline regex whose `(.+)$` capture includes the carriage return on CRLF files. Splitting that captured value on `\s+` creates a trailing empty token, producing `Invalid profile assignment in Potato:`. This was reproduced on the clean published checkout before the fix. Both parsers now trim the capture before splitting. `scripts/tests/profile-config-tests.ps1` exercises both LF and CRLF fixtures; all five profiles, defaults, option ranges, labels, and tooltip keys pass. Actual loader menu selection and persistence remain untested.
2. **Underwater fog endpoint.** `shaders/lib/fog.glsl` formerly fed `isEyeInWater == 1` into `zephAtmosphereFactor`, which multiplies the Hermite distance factor by open-air horizon and weather terms. At a clear vertical view and `fogEnd`, Balanced's factor was `1 × 0.82 × 0.84 × 1.06 = 0.730128`, so it could not blend fully to the loader fog endpoint. All immersed media now use the clamped loader `fogStart`/`fogEnd` range. Low through Ultra retain their small water strength multipliers; Potato, lava and powder snow use the unmodified range. Above-water atmosphere and fog colour paths are unchanged. `scripts/tests/math-regression.ps1` locks the source branch and checks start/end/range cases for media 1–3 and tiers 0–4. This proves source arithmetic and standalone compilation, not rendered water appearance.

The historical Ultra black-crush, full-bright cave, and tooltip issues are documented V1.0.5 work. No current loader output or controlled V1.0.6 screenshot establishes that they recur, so Phase 1 does not alter the lightmap, toe/shoulder, saturation, water Fresnel, or night lighting.

## Performance and GPU portability

The underwater path now avoids the open-air Hermite/horizon/rain factor and uses one clamped distance division with an optional tier multiplier. This is a structural reduction in source work for underwater fragments. Compiler instruction selection and frame pacing are unknown. The required lightmap sample remains; deleting it would restore a known lighting defect. Water specular and analytical sky/cloud paths remain candidates for profiling after a GPU-heavy scene is measured. **PERFORMANCE IMPROVEMENT: NOT YET PROVEN.** No three-trial matched V1.0.5/V1.0.6 benchmark, GPU timing, median/p95 frame time, or 1% low FPS exists.

Standalone WSL `glslangValidator` checks GLSL syntax and linked interfaces for Zepholume-preprocessed variants. The portability matrix inserts vendor/renderer, loader-model and capability macros; it does **not** compile on NVIDIA, AMD, Intel or Mesa drivers. No real-device or in-game GPU compatibility claim is made. `#version 330 compatibility` and fixed-function compatibility inputs remain requirements, so hardware lacking the loader's needed OpenGL compatibility surface is not advertised as supported.
