# V1.0.7 Phase 1 atmosphere workstream

Scope: local development worktree `codex/v107-phase1`, 2026-10-29. Production edits are confined to `shaders/lib/atmosphere.glsl`, `cloud_vertex.glsl`, and `cloud_fragment.glsl`. Existing grading, sky colours, directional lighting, medium-specific fog, profile settings and dimension topology are preserved. No Minecraft launch, matched game screenshot or game frame-time series was produced by this workstream.

## Baseline and reproduced defects

The unchanged V1.0.6 source passes the existing 1,008-case camera regression and 450-case water interpolation regression. The new `scripts/tests/v107-atmosphere-tests.py` exits 1 against the original production source, with `Open-air fog does not preserve endpoints`; the exact rejection is retained in `artifacts/v107-phase1/atmosphere-baseline-rejection.log`.

1. Enabled open-air atmosphere multiplied an already clamped Hermite distance factor by horizon and weather density. At `fogEnd` and every greater distance, clear vertical views reached only **0.6888** fog; clear horizon views reached only **0.84**. This leaves the rest of the original geometry colour visible indefinitely. Potato's linear atmosphere path already reaches its endpoint.
2. Enabled cloud fog similarly reached only **0.76** in clear weather at or beyond `fogEnd`. This concerns distance fog; it is independent of the cloud-lighting quality toggle.
3. Cloud vertices passed `length(viewPosition.xyz)` as a scalar varying. Length is nonlinear, so triangulating the same cloud plane differently changes the interpolated distance. The 432 CPU fixtures reproduce up to **0.9903933489922592** distance difference between opposite diagonals and **2.549061352768089** distance error against the actual fragment position. This is the same mathematical class of defect previously fixed for terrain/water, in a separate source path that still retained it.

These are source/numerical defects. Their severity or appearance in Minecraft has not been observed for this candidate.

## Corrections and cost

Interior fog shaping now uses `g(t) = t * (density + (1 - density) * t)` rather than `t * density`. Here `t` remains the existing Hermite distance curve for air and the existing linear distance for clouds. Both loader endpoints are exact: `g(0)=0` and `g(1)=1`. Density still changes the interior and remains continuous through weather and camera elevation. Over the existing air density range `[0.6888, 1.12]`, the derivative is at least `0.6888`; cloud density `[0.76, 1]` is also monotone. Existing invalid-range steps and immersed-water/lava/snow handling remain intact.

This adds a small multiply/add expression on enabled fog paths without a division, texture sample, transcendental operation or pass. Interior fog is intentionally stronger in clear weather than the legacy curve: at the normalized midpoint, clear horizontal air changes from `0.42` to `0.46`, clear vertical air from `0.3444` to `0.4222`, and cloud fog from `0.38` to `0.44`. Actual scene appearance requires matched runtime review; these are not colour/exposure parameter changes.

Clouds now interpolate the raw view-space position and calculate its length per fragment. This removes the vertex length and changes one scalar varying into a three-component varying, but adds fragment-local length work. It is a correctness tradeoff with potentially higher fragment cost, including Potato. The fix makes both diagonals agree with the affine position reference; no Minecraft performance gain is claimed.

Rejected/deferred changes: no global brightness/contrast retuning, artificial cave fill or extra atmosphere pipeline. The sky's vertex-normalized direction/scalar zenith varyings warrant a separate controlled geometry audit; they were not changed without a dedicated sky-native fixture. Fog/sky colour matching, cloud illumination, night balance and modded dimensions still need game evidence.
