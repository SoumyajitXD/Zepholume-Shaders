An independent `git archive` of checkpoint `3d92f57` supplied a retained LF fixture at `C:\Users\acebi\AppData\Local\Temp\zepholume-lf-fixture-c4eb5f7162b94f16a5bfd232e8105c40`. Its validator and benchmark suites both returned exit 0. The benchmark suite passed 43 synthetic checks. Exact pre/post SHA-256 hashes of `bench/run-manifest-template.json`, `bench/v103-control.json`, and `docs/BENCHMARK_PROTOCOL.md` were unchanged. Evidence is in ignored `artifacts/v107-phase1/tooling/lf-fixture-hashes.json` and `lf-baseline-*.txt`.

The old validator printed 36 rejection lines, but one claimed that a missing optional V1.0.4 archive had been rejected. Actual exercised negative coverage was 35 controls: 32 source mutations and three malformed ZIPs. The new test prints an explicit SKIP when that historical archive is absent and counts executed rejections. Two development-metadata mutations increase actual candidate coverage to 37 controls in a fresh checkout.

The benchmark tests themselves did not change those files on Windows, including LF input. A later fresh upstream checkout reproduced all three dirty files **before any test ran**, identifying a different cause: upstream `.gitattributes` requires LF while the committed blobs contain CRLF or mixed line endings. Git normalizes their content for comparison and reports a dirty tree immediately. The same attribute-only negative control reproduced all three paths with Linux Git under WSL. Adding three narrowly scoped `-text` exceptions preserves every original blob byte and yields clean fresh Windows and Linux checkouts. The CI workflow now checks cleanliness both before and after tests. A hosted run has not been executed; Kali WSL has no PowerShell executable. No software was installed.

The starting checkout lacked `docs/CI_AND_RELEASE_QUALIFICATION.md`; it and the newer upstream workflow, release-evidence gate, six CI helpers and profile-parser CRLF/BOM fix were subsequently imported from verified live upstream `7ead636`, with the existing V1.0.7 tests integrated. Git's remote-tracking `origin/main` was refreshed. The local branch still has a different ancestry and is not a replacement for upstream history.

## Confirmed packaging corrections

The new `scripts/tests/package-tests.ps1` copies the builder into a disposable fixture with a deliberately minimal validator. It tests builder behavior independently of the real validator suite. Against the inherited builder, six of ten assertions failed:

- `Sort-Object` used culture-sensitive ordering although the manifest advertised ordinal ordering. The builder now uses an ordinal sorted dictionary of normalized paths.
- Relative `OutputDirectory` followed the process's .NET current directory rather than PowerShell's current location. It now resolves through the PowerShell path API.
- Manifest output was written directly to its final path before ZIP/sidecar promotion. An injected competing manifest was overwritten, while an injected hash-sidecar conflict left an incomplete ZIP and manifest. The builder now stages all three files, moves without overwrite, publishes the manifest last, and removes only outputs successfully promoted by this invocation when a later move fails. Staging cleanup also covers compression failures.

The revised builder passes all ten checks: ordinal order, repeat-build byte identity, existing archive preservation, relative location, and two injected promotion conflicts with competitor preservation and owned-output cleanup. Before/after logs are `artifacts/v107-phase1/tooling/package-before.txt` and `package-after.txt`. Its default archive name is explicitly `Zepholume-Shaders-1.0.7-dev-phase1.zip`.

This is not a three-file filesystem transaction. Process termination or power loss between moves can still leave partial outputs; the manifest is the completion marker. The builder does not defend against hostile concurrent replacement of its just-promoted files. Package byte identity is asserted for identical payload bytes and this runtime, not different compressor implementations or differently normalized checkouts.

## Test isolation and CI

`scripts/tests/benchmark-isolation-tests.ps1` copies only the benchmark suite's declared inputs into fresh LF and CRLF fixture trees. Each runs the existing 43 synthetic checks, then compares the exact bytes of the three reported mutable fixtures. A deliberate added newline is rejected by each guard. Original repository inputs are separately checked unchanged. The separate attributes fix addresses the independently reproduced pre-test checkout issue.

The validator requires V1.0.7 Phase 1 development identity in README, shader properties and changelog while retaining required historical headings. Its tests discover the current trusted PowerShell executable and verify the absolute temporary cleanup boundary.

CI retains the existing strict tracked-diff gate and adds an initial checkout check. Linux regression coverage adds benchmark isolation, package behavior, and the new atmosphere and water-specular CPU regressions. Windows smoke adds package behavior and the inherited output-safety, collector and warning checks. The generated variant artifact path also uses a single portable slash; the upstream CI coverage validator accepts all 5,040 mappings. Native GPU cases remain local driver evidence and are not labelled hosted coverage.
