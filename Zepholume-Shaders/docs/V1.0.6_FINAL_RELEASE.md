## Production changes and final audit

The actual frozen V1.0.5 release ZIP has SHA-256 `4B3803CF87AF43952CF91D145BB634C3346DEF6FC8C7008C37368058DC75DC91`. Both it and final source contain 132 shader-tree paths. V1.0.6 incorporates these proven source corrections:

- Preserve exact positive loader fog ranges, including sub-block/tiny ranges, in immersed, open-air and cloud paths; define a step for equal/reversed endpoints. Underwater distance fog bypasses open-air horizon/weather shaping.
- Compare view-space celestial directions and normals with camera-transformed world up for lighting, sky, clouds, fog, materials and dimension fill.
- Preserve Phase 8's affine view-ray interpolation and fragment-local distance. Normalized corner rays and interpolated corner lengths no longer create the reproduced planar diagonal discontinuity.
- Preserve the Phase 8 lightmap flag before the shared fragment include in all four hand routes. Lightmap multiplication occurs before existing hand grading, with source alpha retained.
- Retain compile-time removal of disabled cloud work, reused water celestial weights and the corrected cloud-fog setting label.

Ordinary scene lightmap consumption, water-only material classification, complete wrappers, texture-matrix coordinates and positive-toe grading were already in V1.0.5 and remain preserved. Finalization introduced **no new GLSL algorithm or numeric profile change**. Relative to the exact Phase 8 package, only `README.md`, `CHANGELOG.md` and the `shaders.properties` release comment changed in the packaged payload.

The final audit found no additional confirmed GLSL blocker. No speculative optimization, global brightness retuning, shadow map, SSR, new rendering pass or heavyweight abstraction was added. The hand uses existing shared fog behavior; an older report's claimed hand-specific no-fog policy was inaccurate and is not a release claim.

| Concern | Final classification |
| --- | --- |
| Located diagonal interpolation error | **Confirmed resolved** in source/numerical/native fixtures; photographed waterfall outcome **unverified**, overall symptom only partially corrected pending attribution |

| Analytical water local skylight occlusion | **Unresolved confirmed source limitation**; gameplay severity and screenshot causality **unverified** |
| Night/cave/interior balance, transparency sorting/depth/alpha composition | **Unverified** in Minecraft |

Water base colour is lightmapped before analytical sky reflection and celestial highlights are added. Those later terms lack local directional sky visibility. `zephLightCoord.y` supplies propagated ambient skylight, not a reliable occlusion test. A new multiplier could incorrectly darken open water/overhang edges; total irradiance could let torches enable sky reflection. The final decision is to preserve established behavior and disclose this limitation, with no speculative attenuation or architectural addition.

No final Minecraft gameplay, loader-patched GLSL, profile-menu selection, dimension-transition, matched screenshot, real fluid mesh, transparency composition or frame-time/FPS test was performed. Standalone draws disable game blending/depth/sorting and cannot establish those outcomes. Other GPU vendors remain untested.

Historical Phase 8 flat-quad timing showed about 3.1% lower water query time and 2.44% higher hand query time with A/A drift below 0.16%. These were **not rerun as final timing measurements** and are **not Minecraft FPS gains or regressions**. The required hand lightmap fetch remains for correctness.
